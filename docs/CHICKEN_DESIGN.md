# Chicken Yard presentation and asset contract

M0-F05 chooses two views, Field and Chicken Yard, inside the existing /play/ world. They share one engine/state, clock, tank, Coins/Market and storage session. The existing eight-bed coordinate layout remains untouched. Camera and active-area selection are presentation state. The Yard uses the same900×540 SVG coordinate frame and8×8 ground extent, with fence, fixed coop/ramp and separate selectable feeder/drinker/cleanup/nest. Configured footprints and all planned coop tiers fit without overlap; hen waypoints avoid structures. A nest is a sub-part of the coop, not a second conflicting building footprint.

Keep one guide/objective appropriate to the active area. Area buttons and HTML object shortcuts provide ≥44px targets; all SVG interactions have keyboard/HTML equivalents. The existing SVG/mobile fallback is verified in Chromium touch320/360/390 and Firefox, with reduced-motion support. New yard rendering will reuse that pipeline and be checked incrementally in M1; this audit does not claim that yet-unimplemented Chicken UI or production works.

Asset inventory: original project FarmGirl PNG and optimized game portrait retained as existing approved media; no FarmGirl homepage portrait. Field trees/tiles/crops are existing original SVG constructors. Coop, fence, ramp, hens, feeder, drinker, nest and future homepage farm-vision artwork will be original repo-native SVG shapes in the established style, with no commercial/reference assets or external runtime. Future goat/cow/fish imagery is illustration only, explicitly labelled EN/ID; only chickens gain mechanics. No WebGL/rigging/dependency addition is needed. Animation uses CSS transforms/short paths, is state-driven, and stops with reduced motion/low mode; it never produces eggs.

View rotation will reproject grid coordinates at quarter-turn orientations while keeping vertical structures upright (an isometric visual, not a rewritten 3D engine). DOM/SVG hit targets move with the projection. Bounded zoom/pan and reset are per area and never dispatch simulation commands. Visible left/right rotate and zoom/reset buttons work without gestures. Drag movement thresholds protect taps; page scrolling remains available outside the map and ordinary wheel scroll is not intercepted.

M1-F07 implements separate Field/Yard presentation cameras: four90-degree orientations, zoom0.85–1.75, bounded pan±180/±100, reset to active area's default. Six44px controls include explicit Move mode; default touch-action pan-y permits vertical page scroll, while Move mode intentionally enables two-axis map drag. Ordinary wheel events are not cancelled; Ctrl/Meta-wheel optionally zooms. Focused SVG supports arrows, bracket rotation, +/- and Home/0 reset. Camera preferences are not written into the game save; reload safely starts with default views. DOM picking reprojects with actual world coordinates, including pump pipes, and build coordinates remain fixed.

Camera QA uses mouse, actual CDP touch drags/taps, keyboard,390px portrait and844×390 landscape in both languages. Each of four angles selects a visible crop bed and adds/selects a new bed from the same synthetic progressedV1 fixture, checking the exact cost/placement and revisions. Yard object selection and rendering never change save bytes; view controls likewise leave tick/RNG/Coins/ledger/resources/missions exact. Coop upgrade footprints are verified as snapshots now; actual Chicken purchase/upgrade mechanics are verified when M3/M5 introduce them. During review, decorative irrigation pipes and passive notices were found intercepting bed input and made non-interactive. Coop wall/roof and actor/fence depth ordering were corrected for reverse views. Mobile controls were moved into one non-occluding row above the scene. Rotated screenshots are retained outside Git.

The MyZooTwin public URL could not be opened by the web tool in this environment. Controls follow the explicit PRD experience contract; no code or assets from that reference were copied, and no unsupported claim about its implementation is made.

Domain references inspected for causal direction only: [UMN Extension](https://extension.umn.edu/agriculture/animals-and-livestock/poultry/raising-chickens-for-eggs) on feed, fresh water, care and shelter; [UK welfare code](https://www.gov.uk/government/publications/poultry-on-farm-welfare/poultry-welfare-recommendations) on hygiene, environment and heat; [UF/IFAS egg facts](https://ask.ifas.ufl.edu/publication/VM262) search text and [University of Kentucky extension](https://poultry.extension.org/articles/poultry-related-youth-programs/do-you-need-a-rooster-for-a-hen-to-lay-an-egg/) on hens laying without a rooster. The IFAS page-open route redirected in a loop; it was not represented as a successfully opened page. No reference text or images are copied into the game. All numerical rates, probabilities, prices and durations are fictional gameplay approximations, never husbandry advice.
