# Isolated build and rollback

`node tools/build.mjs` copies approved web-file extensions from `game/client` into `dist/play` only. It does not delete directories, process editorial HTML, or clean dist. Source symlinks are rejected. The integration test builds twice into a temporary fixture, confirming byte-identical homepage, shared styles and category content. This test runs before a real game source is introduced.

The hidden unified-world experiment uses pinned Three.js 0.187.0 and esbuild 0.28.2. The default entry is bundled separately and does not fetch world graphics. The optional preview shares a tree-shaken CPU/math chunk with its Canvas fallback and loads a version-bound WebGL driver chunk asynchronously. The same class instances are shared across those chunks. Standalone game modules remain available for rollback and diagnostics; actual default-entry resources, optional graphics and retained modules are reported separately by performance QA. No dependency directory or source maps are published. The full upstream MIT notice and exact version receipt remain under `dist/play/vendor/three`.

`tools/bundle-world.mjs` generates into `dist/play` with esbuild `write:false`, validates resolved output paths, then writes the approved outputs. Only stale generated files owned by the preceding build receipt may be removed, after verifying their bytes. Modified generated files block cleanup. The obsolete raw Three core copy is removed only when it exactly matches the installed pinned package. No recursive directory cleanup or editorial processing occurs. `build-info.json` records generated hashes, the lazy driver and actual default-entry resources. Isolated tests check shared CPU/renderer class identity, stale-file ownership, modified-file refusal, notice/pin checks and retained editorial bytes. `tools/unified-build-audit.mjs --before` freezes actual editorial/original-media bytes outside the game build; running it after build checks exact preservation, generated hashes and the distributed notice.

Receipt-bound game entry HTML/CSS and the small preview loader use canonical LF output. Generated entry/bundle/receipt files have explicit LF Git attributes; upstream vendor bytes retain `-text`. This prevents Windows `core.autocrlf` from making committed/Linux-served resource hashes disagree with the tested local receipt. Only the named game entry text files are normalized; editorial files, media and save fixtures are not processed. The build test includes CRLF entry inputs and exact preserved editorial bytes.

Before release, hash all editorial assets and compare against the M0 baseline, allowing only explicitly reviewed homepage/nav/sitemap/canonical changes. Rollback is a Git revert of the release commit followed by the same audited deployment route. Preserve browser saves; do not remove storage during deployment. Never change nameservers or audience.
